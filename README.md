# Telegram Shop Bot с поиском товаров по фотографии (Railway Ready)

Полноценный backend Telegram-бота для интернет-магазина с поиском товаров по фотографии из каталога Telegram-канала, очередью задач в PostgreSQL, регистрацией по подтверждённому номеру телефона, административной панелью в Telegram и деплоем на платформу **Railway**.

---

## 1. Архитектура и принципы работы

1. **Единый сервис + PostgreSQL**:
   - Webhook быстро сохраняет входящие обновления Telegram в таблицу `processed_updates` (идемпотентность по `update_id`) и ставит задачу в очередь `jobs`. Клиенту сразу возвращается HTTP 200 OK.
   - Фоновый воркер захватывает задачи с помощью `SELECT ... FOR UPDATE SKIP LOCKED` с поддержкой аренды (lease), heartbeat и экспоненциального backoff. Очередь персистентна в БД и устойчива к перезапускам сервиса.
2. **Двухэтапный поиск**:
   - **Этап 1 (Точные копии)**: Perceptual Hash (64-битный DCT pHash) со сравнением расстояния Хэмминга (`PHASH_MAX_DISTANCE <= 6`). Мгновенный результат без затрат на API.
   - **Этап 2 (Визуальное сходство)**: Векторные эмбеддинги реального мультимодального API (**Voyage AI** `voyage-multimodal-3.5`, принимающий изображения через Base64).
   - **Принятие решений**: Учитываются два параметра — порог уверенности `MATCH_THRESHOLD` и минимальный отрыв от второго кандидата `MATCH_MARGIN`. Если товар не найден или результат спорный — формируется заявка администратору в `ADMIN_CHAT_ID`.
3. **Каталог товаров**:
   - Пополняется автоматически из постов и альбомов канала `CHANNEL_ID`.
   - Альбом (`media_group_id`) собирается воедино, даже если подпись пришла только к одной фотографии.
   - Поддерживается ручная деактивация (`/deactivate`) и импорт старых постов пересылкой (`/import`).

## 3. Провайдер эмбеддингов: Voyage AI

- **Модель**: `voyage-multimodal-3.5` (или `voyage-multimodal-3`).
- **Endpoint**: `https://api.voyageai.com/v1/multimodalembeddings`.
- **Тип входных данных**: `image_base64` в формате `data:image/jpeg;base64,...`.
- **Стоимость запросов**:
  - Первые **150 миллиардов пикселей** (и 200 млн токенов) предоставляются бесплатно.
  - Далее: **$0.60 за 1 млрд пикселей**. Картинка с уменьшенной стороной 1024 px стоит около **$0.0003–$0.0006** за вычисление вектора.
- **Ключ API**: Получается бесплатно в консоли [dash.voyageai.com](https://dash.voyageai.com/).
- **Режим без ключа**: Если `IMAGE_EMBEDDING_API_KEY` не задан, бот не имитирует поиск, а честно предупреждает в логах и админ-панели: работает только этап 1 (точный pHash).

## 5. Инструкция настройки BotFather и Telegram-канала

1. **Создание бота**:
   - Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, укажите имя и username.
   - Скопируйте полученный токен в `BOT_TOKEN`.
   - Включите чтение каналов: в BotFather выберите `/mybots` → ваш бот → **Bot Settings** → **Group Privacy** → **Turn off** (чтобы бот гарантированно получал все сообщения при добавлении в группы).
2. **Настройка канала магазина**:
   - Добавьте созданного бота в администраторы канала магазина с правом **Post Messages** (или хотя бы правом на чтение/редактирование).
   - Узнайте числовой ID канала: перешлите любой пост из канала боту [@userinfobot](https://t.me/userinfobot) или воспользуйтесь командой `/chatid`, добавив бота временно в канал/группу. ID каналов обычно начинается с `-100...`. Укажите его в `CHANNEL_ID`.
3. **Настройка чата администраторов**:
   - Создайте группу для менеджеров/администраторов или используйте личный чат.
   - Добавьте бота в группу. Отправьте команду `/chatid` — бот вернёт ID чата. Укажите его в `ADMIN_CHAT_ID`.
   - Узнайте свой личный Telegram ID (через команду бота `/myid` в ЛС) и укажите его в `ADMIN_IDS`.

## 6. Деплой на Railway с PostgreSQL

1. **Создание проекта**:
   - Зайдите на [railway.com](https://railway.com/) и создайте новый проект (**New Project**).
2. **Добавление PostgreSQL**:
   - Нажмите **+ New** → **Database** → **Add PostgreSQL**.
   - Railway создаст базу данных и предоставит переменную `${{Postgres.DATABASE_URL}}`.
3. **Деплой сервиса из GitHub**:
   - Нажмите **+ New** → **GitHub Repo** → выберите репозиторий с этим проектом.
   - В настройках сервиса (**Settings**):
     - В разделе **Networking** нажмите **Generate Domain** (получите домен вида `xxx.up.railway.app`).
   - В разделе **Variables** добавьте переменные:
     - `DATABASE_URL`: подставьте `${{Postgres.DATABASE_URL}}`
     - `BOT_TOKEN`: токен от BotFather
     - `CHANNEL_ID`: ID канала (например `-1001234567890`)
     - `ADMIN_CHAT_ID`: ID админ-чата
     - `ADMIN_IDS`: ваши Telegram ID через запятую
     - `BOT_MODE`: `webhook`
     - `APP_BASE_URL`: `https://xxx.up.railway.app`
     - `WEBHOOK_SECRET`: произвольная секретная строка
     - `IMAGE_EMBEDDING_API_KEY`: ключ Voyage AI
4. **Автоматические миграции и запуск**:
   - Благодаря файлу `railway.toml`, Railway выполнит `preDeployCommand = ["alembic", "upgrade", "head"]` перед стартом контейнера.
   - После успешного прохождения миграций запустится сервис, зарегистрирует вебхук в Telegram и начнет отдавать 200 на `/health`.

## 7. Локальный запуск (для разработки)

1. Клонируйте проект и активируйте виртуальное окружение:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. Поднимите локальный PostgreSQL и примените миграции:
   ```bash
   export DATABASE_URL=postgresql://postgres:postgres@localhost:5432/shopbot
   alembic upgrade head
   ```
3. Для локального тестирования без белого IP переключите режим на polling:
   - В файле `.env` укажите:
     ```env
     BOT_MODE=polling
     POLLING_DELETE_WEBHOOK=true
     ```
4. Запустите приложение:
   ```bash
   python -m app
   ```

## 8. Порядок импорта существующих товаров

Так как Telegram Bot API не предоставляет метода чтения истории сообщений канала:
1. Администратор (чей ID указан в `ADMIN_IDS`) открывает канал магазина в Telegram.
2. Выделяет ранее опубликованные посты (посты-альбомы пересылаются целиком).
3. Нажимает **«Переслать»** и отправляет их в личные сообщения боту.
4. Бот проверяет источник (`forward_origin.chat.id == CHANNEL_ID`):
   - Если пост из канала магазина — сохраняет товар, ссылку на оригинальный пост в канале и ставит фото в очередь на вычисление pHash и эмбеддингов.
   - Через несколько секунд администратору приходит отчёт по каждому импортированному товару с извлечёнными полями (цена, размеры, артикул).
5. **Важно**: Если в канале включена защита контента (**Restrict saving content** / запрет пересылки), Telegram не передаст пересылаемый пост боту. В таком случае на время первоначального импорта ограничение в настройках канала временно отключается, либо используется разовый импорт через пользовательский MTProto-скрипт (Telethon/Pyrogram).

## 9. Порядок калибровки поиска на реальных фотографиях

Визуальная близость сильно зависит от специфики товаров (обувь, одежда, аксессуары):
1. В базе данных ведётся техническая таблица `search_logs`, куда записываются:
   - `stage`: сработал ли pHash или векторный поиск;
   - `top1_score` и `top2_score`: косинусная близость лучшего и второго кандидатов;
   - `outcome`: `match`, `uncertain` или `not_found`.
2. После добавления первых 30–50 товаров в каталог протестируйте бот:
   - Отправьте исходное фото из канала (должно сработать по pHash за 0.1 сек).
   - Отправьте скриншот с экрана смартфона (этап pHash или эмбеддинг > 0.90).
   - Сфотографируйте товар на камеру под другим ракурсом/с другим фоном.
3. Проанализируйте оценки в базе данных:
   ```sql
   SELECT outcome, stage, top1_score, (top1_score - top2_score) as margin, count(*)
   FROM search_logs GROUP BY 1, 2, 3, 4;
   ```
4. Скорректируйте переменные в окружении:
   - Если бот путает похожие модели одной марки — увеличьте `MATCH_MARGIN` (например, с `0.03` до `0.05`) или `MATCH_THRESHOLD` (с `0.86` до `0.88`).
   - Если бот слишком часто отправляет заявки админу при очевидном совпадении — снизьте `MATCH_THRESHOLD` до `0.83–0.84`.

## 10. Честный список ограничений и оставшихся действий

1. **Необходимые ваши аккаунты и ключи**:
   - Токен Telegram бота (создать через @BotFather).
   - Ключ API Voyage AI (зарегистрироваться на dash.voyageai.com).
   - Аккаунт Railway для деплоя PostgreSQL и сервиса.
2. **Ограничения Telegram file_id**:
   - `file_id` генерируется серверами Telegram и валиден только для конкретного бота. Если вы смените токен бота, старые `file_id` перестанут открываться при попытке повторной отправки. В коде предусмотрен fallback (карточка отправится текстом, если `send_photo` выдаст ошибку). Для постоянного независимого архива фотографий клиентов в будущем можно подключить S3-совместимое хранилище (AWS S3, Cloudflare R2, MinIO).
3. **Удаление постов в канале**:
   - Telegram Bot API не отправляет событие об удалении обычного поста в канале. Если товар распродан или пост удалён, администратор скрывает его командой `/deactivate <номер|ссылка>`.
4. **Масштабирование векторного поиска**:
   - Текущая реализация хранит эмбеддинги в PostgreSQL и загружает матрицу векторов активных товаров в память процесса (in-memory cosine similarity через NumPy). Для каталогов до 20 000 – 50 000 товаров это работает за доли миллисекунды. При росте каталога свыше 100 000 товаров рекомендуется включить расширение `pgvector` в PostgreSQL и создать HNSW/IVFFlat индекс.
